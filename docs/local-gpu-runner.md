# Local macOS GPU runner

The five-hour model-research workflow uses a self-hosted GitHub Actions runner with the
custom label `dysarthria-gpu`. CI and security analysis continue to use isolated
GitHub-hosted runners.

## Requirements

- An Apple Silicon Mac with Metal acceleration, or a CUDA machine
- The machine connected to power and awake during scheduled runs
- A dedicated, non-administrator macOS account for the Actions runner
- A licensed dataset stored outside the repository
- A pseudonymous CSV manifest following `data/README.md`

## Register the runner

1. Open the repository on GitHub.
2. Go to **Settings → Actions → Runners → New self-hosted runner**.
3. Select macOS and the correct architecture.
4. Run the exact download and verification commands generated by GitHub.
5. During `config.sh`, add the custom label `dysarthria-gpu`.
6. Install and start the runner service using the commands generated by GitHub.

Registration tokens are short-lived secrets. Never paste one into chat, a commit, a log, or
an issue.

## Configure private data

In the runner application directory, create a local `.env` file that is readable only by
the dedicated runner account:

```text
DYSARTHRIA_MANIFEST=/absolute/private/path/dysarthria_manifest.csv
```

The manifest and audio paths must remain outside the Git checkout. Do not expose participant
names or direct identifiers. Keep the dataset read-only for the runner account where
practical.

## Validate the machine

After the repository dependencies are installed, run:

```bash
uv sync --extra dev --extra model --locked
uv run python verify_runner.py --manifest "$DYSARTHRIA_MANIFEST"
```

The check must report either `mps:Apple Metal` or a CUDA device. Intel Macs without a
supported accelerator are not suitable for the scheduled WavLM research workflow.

## Public-repository precautions

- Never add a pull-request trigger to the self-hosted workflow.
- Require pull requests and passing CI for changes to `main`.
- Restrict workflow-file changes through CODEOWNERS review.
- Do not store unrelated credentials in the runner account.
- Keep the runner and macOS patched.
- Review Actions logs and stop the runner immediately if unexpected code executes.

The Mac must be awake and online when a cycle becomes due. GitHub will queue the job while
the runner is offline, but the experiment cannot run until the runner reconnects.

## Sleep, lid closure, and shutdown behavior

The runner is a process on the Mac. If the Mac is shut down, loses power, or sleeps in a way
that stops the runner service, the active GitHub Actions job stops. GitHub does not migrate
that running process to another machine. When the runner reconnects, a queued scheduled job
may start again from the beginning; training checkpoints are required if an experiment must
resume rather than restart.

For unattended runs, connect the Mac to power and configure macOS to prevent sleep while it
is connected to the charger. A lid-closed run requires supported clamshell operation, power,
and an external display or input device. Test the runner with a short manual workflow before
using a long experiment.

For a temporary local keep-awake period, run this in a separate Terminal session:

```bash
caffeinate -dimsu
```

Stop `caffeinate` after the experiment or close the Terminal session. This cannot keep a
powered-off Mac running.

If the Mac will be unavailable regularly, use a dedicated always-on machine or a cloud GPU
runner instead. A self-hosted laptop runner cannot provide uninterrupted five-hour research
cycles while the laptop is off.
